CES utility maximization: $U(x) = (\sum_i w_i x_i^r)^{1/r}$, $r=0.5$,
maximized subject to budget $p^\top x = M$, $x \ge 0$; $w=(1,2,3)$,
$p=(1,1,2)$, $M=100$. Equivalent (monotonic transform) to maximizing
$f(x) = \sum_i w_i x_i^r$.

Closed-form CES demand (independent Lagrangian derivation, verified in-script
by checking the stationarity ratio $r w_i x_i^{r-1}/p_i$ is constant across
$i$): $x_i^\star = C (w_i/p_i)^2$, $C = M / \sum_j (w_j^2/p_j)$.

$x^\star = (10.5263, 42.1053, 23.6842)$, $f^\star = 30.8220700148$.

Note: the x-vector inf-norm error (6.58e-3) is materially larger than the
objective error (5.8e-8). This reproduces a previously-logged effect: power
cones whose "constant" slot (here $s_2=1$, the third triple coordinate) is a
FIXED value baked into $h$ rather than a free variable pinned by an
equality constraint show a coarser x-precision floor than the objective
precision, first observed and logged 2026-08-02 (quad-over-lin run,
not filed as a bug there either). This run reproduces that same pattern in
the *opposite* cone orientation (concave epigraph $t \le x^r$ vs. that run's
convex epigraph $t \ge x^2/y$), which strengthens rather than weakens the
"expected precision-floor, not a bug" reading -- it is not specific to one
orientation.

* Verdict

PASS. Objective-level agreement across all three independent checks
(closed form, CLARABEL, SCS) is well within tolerance. The x-precision gap
is consistent with an already-logged, not-filed effect and is noted here as
a second confirming data point rather than a new finding.
