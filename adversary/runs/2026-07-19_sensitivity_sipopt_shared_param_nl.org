* Problem
:PROPERTIES:
:FAMILY: sensitivity
:CLASS: NLP parametric sensitivity via the sIPOPT CLI suffix path; parameter appears nonlinearly in BOTH the objective and the constraint
:SOURCE: Pirnay, Lopez-Negrete & Biegler, "Optimal sensitivity based on IPOPT", Math. Prog. Comp. 4 (2012) 307-331 (sens_state_1 / sens_state_value_1 / sens_init_constr protocol); Fiacco (1983) Thm 2.1, dx/dp = -(KKT)^{-1} d(grad L)/dp
:KNOWN_OPTIMAL: x*(p=1) = (1.12221582910917, 0.35111366835633) — exact closed form; dx/dp = (1.15855543, -0.13364490)
:N_VARIABLES: 3 (x0, x1, and the pinned parameter p)
:N_CONSTRAINTS: 2 equalities (one physical, one sens_init_constr pin)
:END:

\begin{align*}
\min_{x_0,x_1}\quad & (x_0 - p)^2 + (x_1 - 1)^2 + e^{p} x_1^2 \\
\text{s.t.}\quad & x_0 + 2x_1 + \tfrac12 p\, x_1 = 1 + p \\
                 & p = 1 \qquad \text{(nominal, pinned by \texttt{sens\_init\_constr})}
\end{align*}

Perturbed parameter value declared via =sens_state_value_1=: $p = 1 + \Delta p$
for $\Delta p \in \{0.2,\ 0.02\}$.

** Why this instance

The existing 2026-06-09 sIPOPT run reused the upstream =parametric.nl= fixture,
where $p$ enters **only** the constraints and $x^*(p)$ is **affine** — so the
first-order predictor is exact and cannot distinguish a correct sensitivity from
a lucky re-solve. Here:

- $p$ enters the *objective twice* — in $(x_0-p)^2$ and nonlinearly as
  $e^{p}x_1^2$ — *and the constraint twice* (bilinear $\tfrac12 p x_1$, and the
  rhs). An implementation that drops the objective's $\partial(\nabla_x f)/\partial p$
  term, or the constraint Jacobian's $p$-dependence, gets a visibly wrong answer.
- $x^*(p)$ is genuinely *nonlinear* in $p$, so the first-order predictor is
  **not** the re-solve. This lets us verify the returned quantity is a true
  first derivative by checking the predictor/re-solve gap shrinks *quadratically*
  in $\Delta p$.

The .nl (with all three sIPOPT suffixes) is generated by Pyomo inside the run
script; no pounce source or fixture was modified.

** FD step-size plateau sweep

The oracle is an *exact closed-form* re-solve: for fixed $p$ the objective is a
strictly convex quadratic in $x$ and the constraint is linear in $x$, so
$x^*(p)$ solves a 3×3 KKT linear system in float64. This avoids the ~1e-9
solution noise an SLSQP re-solve would inject into the finite difference. The
closed form was cross-checked against scipy SLSQP: inf-err 3.49e-10.

* Cross-check / Verification

1. *Forward solve.* pounce's nominal primal from the .sol matches the exact
   closed-form optimum to 2.22e-16 (machine epsilon) at both Δp settings. The
   derivative is being judged against a correct forward solve.
2. *Suffix wiring.* The =sens_sol_state_1= slot for the parameter variable
   reports exactly the requested perturbed value (1.2 and 1.02 respectively),
   confirming the suffix protocol round-trips through the Pyomo-written .nl and
   the .sol reader.
3. *Derivative match.* The implied $dx/dp = (x_{\text{pounce}} - x^*_{\text{nom}})/\Delta p$
   is **identical to 12 digits at both Δp values** and matches the FD plateau
   value to 2.7e-12. A missing objective term would perturb the first component
   at the 1e-1 level; a missing constraint-Jacobian $p$ term would perturb the
   second. Neither is present.
4. *Quadratic shrinkage.* gap(0.2)/gap(0.02) = **98.11**, against the 100.0
   expected for a true first derivative with $O(\Delta p^2)$ truncation. This
   independently confirms =sens_sol_state_1= is a first-order predictor and not,
   e.g., a re-solve or a mis-scaled step.
