#+TITLE: Adversary Run: Does the narrowed divergence guard miss real unboundedness?
#+DATE: <2026-07-22>

* Problem
:PROPERTIES:
:FAMILY:   nlp
:CLASS:    unboundedness detection (false-negative probe)
:SOURCE:   constructed; recession-ray family modelled on jit1's relaxation shape
:KNOWN_OPTIMAL: none (all instances are unbounded below by construction)
:N_VARIABLES:  5, 12, 25
:N_CONSTRAINTS: 1 coupling constraint
:END:

Targets: **PR #249** (issue #248) and **PR #253** (issue #252), which
progressively narrowed when POUNCE reports =DivergingIterates=. A step now
counts toward the firing streak only if all three hold —

#+begin_src rust
growing    : |x|_inf >= 2 * previous |x|_inf
descending : f dropped since the previous step
keeping_up : this drop >= 0.9 * previous drop        // added by #253
#+end_src

— and the streak must reach 4 *consecutive* qualifying steps, with any failing
step resetting it to **zero** (not decrementing it).

Two adversarial hypotheses:

1. *Sub-linear recession.* #253's premise is "a genuine recession ray's per-step
   objective drop keeps up." That is false for objectives diverging to -inf
   sub-linearly (=-log(x)=, =-sqrt(x)=, =-x^0.25=), whose drops decelerate.
2. *Streak stutter.* IPM step lengths stutter (fraction-to-the-boundary, filter
   line search). If the drop ratio dips below 0.9 even once every few
   iterations, the streak can never reach 4 and a genuine ray is missed.

A missed unboundedness is the dangerous direction of error: a spurious UNBOUNDED
is loud and retryable, whereas a silent finite "bound" for a problem that has
none makes a branch-and-bound driver fathom on a bound that does not exist.

* Results
:PROPERTIES:
:STATUS: PASS
:END:

** Hypothesis 2 — streak stutter (the real regression question)

Family: =min sum c_i/x_i - sum d_i x_i=, =x_i >= lo_i=, no upper bound. The
=-d_i x_i= tail makes f -> -inf *linearly*, so the guard should fire. =c= and
=d= span =1e{1,3,5,7,9}= to make the realised steps stutter. Run at
=diverging_iterates_tol=1e6=, the setting a B&B driver uses.

| n  | conditioning sweep | POUNCE    | Ipopt     |
|----+--------------------+-----------+-----------|
|  5 | 1e1 .. 1e9         | UNBOUNDED | UNBOUNDED |
| 12 | 1e1 .. 1e9         | UNBOUNDED | UNBOUNDED |
| 25 | 1e1 .. 1e9         | UNBOUNDED | UNBOUNDED |

**15 / 15 agreement**, every instance =EXIT: Iterates diverging; problem might
be unbounded=. No missed unboundedness. Hypothesis 2 is refuted for this family:
the streak survives the stutter that this level of ill-conditioning produces.

** Hypothesis 1 — sub-linear recession

| Problem              | POUNCE                     | Ipopt (oracle)    |
|----------------------+----------------------------+-------------------|
| =min -log(x), x>=1=  | Optimal, f = -18.77        | Optimal, f = -18.77 |
| =min -sqrt(x), x>=1= | Solved To Acceptable Level | Optimal           |
| =min -x^0.25, x>=1=  | Optimal                    | Optimal           |
| =min -log(x)-log(y)= | Optimal                    | Optimal           |

Both solvers claim a finite optimum on problems that are unbounded below. This
is **not** a POUNCE regression and not attributable to #249/#253: it is inherent
to gradient-based termination. For =f = -log(x)= the gradient =-1/x -> 0=, so
the KKT residual test is satisfied asymptotically and *any* local NLP solver
stops. Ipopt behaves identically, at the same objective value. Recorded as a
shared limitation, not a finding.

* Cross-check / Verification

Ipopt 3.x (=/opt/homebrew/bin/ipopt=) on the byte-identical =.nl= files that
POUNCE was given, with the same =diverging_iterates_tol=. Models generated by
Pyomo so both solvers consume the same file — no hand-built derivatives, which
removes the most common source of false positives in this kind of test.

* Verdict

=PASS=. Neither hypothesis produced a missed unboundedness attributable to the
narrowed guard. #253's stricter firing condition did not trade its false
positive for a false negative on linear recession rays, across a
three-orders-of-magnitude conditioning sweep at three problem sizes.

The sub-linear cases (=-log=) are a genuine blind spot in unboundedness
detection, but a pre-existing and solver-independent one that POUNCE shares
exactly with Ipopt; it is out of scope for these PRs.
