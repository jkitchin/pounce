#+TITLE: Autoroute transparency — pure LP (equality + inequalities) -> lp-ipm
#+DATE: 2026-06-09

* Problem properties
- Family ............ autoroute (pounce.minimize, default solver_selection="auto")
- Class ............. pure linear program (linear objective + linear eq/ineq + nonneg bounds)
- SOURCE ............ self-contained standard-form-ish LP; optimum independently
  verified by scipy.optimize.linprog (HiGHS).
- Expected route .... lp-ipm  (LP detected -> specialized convex LP interior-point,
  pounce.solve_qp with P=0).
- KNOWN_OPTIMAL ..... -5.0  at x* = (3, 1, 0)
  (Correction note: an initial hand guess of (0,2.5,1.5)->-3.5 was a REFERENCE
  error — feasible but not optimal; scipy oracle = -5.0 = both pounce paths.)

* Formulation
  minimize    c.x,        c = [-1, -2, 1]
  subject to  x0 + x1 + x2 = 4          (equality)
              x0 + 2 x1      <= 5        (inequality, active at optimum)
              x1 + x2        <= 3        (inequality)
              x >= 0
  x0 = (4, 0, 0)  (feasible vertex).

* Detection of which solver auto chose
  pounce._minimize._solve_via_convex stamps info["solver"]="lp-ipm" (LP) /
  "qp-ipm" (QP) on the returned OptimizeResult; the NLP fallthrough returns the
  raw NLP info dict, which has NO "solver" key but DOES have "mu" (IPM barrier).
  Here res_auto.info["solver"] == 'lp-ipm' and res_nlp.info has no "solver"
  (has "mu") — auto used the specialized LP IPM, forced-nlp used the general NLP.

* Cross-check

  forced-nlp (filter-IPM). Active-set at optimum (eq + row2 active) is consistent.
