** (b) Do the two links agree?
Yes — byte-for-byte equivalent arithmetic on all three quantities (objective,
equation marginals, variable marginals).  There is **no divergence between
install methods**; both are correct for =minimizing= and both are wrong the
same way for =maximizing=.  =link.py='s =_STATUS_MAP= (:60-78) is likewise
documented as "ported verbatim" from =map_status_to_gams()= in the C link.

** The internal inconsistency
Within each link, the =obj_sign= flip is applied to the objective and to the
*variable* marginals but not to the *equation* marginals.  GAMS uses one and the
same \(\partial\text{obj}/\partial\text{perturbation}\) convention for both
kinds of marginal, so under *any* consistent GAMS convention exactly one of the
two is wrong for max models.  The live oracle above settles which: the variable
marginals are right, the equation marginals are wrong.

** Derivation
Ipopt/POUNCE stationarity is \(\nabla f_{\min} + \nabla c^{\!\top}\lambda - z_L + z_U = 0\),
so \(\partial f^\*_{\min}/\partial\mathrm{rhs} = -\lambda\) and the reduced cost is
\(z_L - z_U\).  For a =minimizing= model \(f_{\min}=f\), so
\(\pi_{\rm GAMS} = -\lambda\) — what both links emit. Correct.
For a =maximizing= model \(f_{\min} = -F\), so
\(\partial F^\*/\partial\mathrm{rhs} = +\lambda\); the correct emission is
\(\pi_{\rm GAMS} = \mathrm{obj\_sign}\cdot(-\lambda) = +\lambda\).  Both links
still emit \(-\lambda\).

* Secondary consequence
=gams/gams_pounce.c:973-1050= (§7.4(a) SQP warm-start reconstruction) reads
=gmoGetEquM= / =gmoGetVarM= back and re-flips assuming its own output
convention.  That is self-consistent when the previous solve was POUNCE's, but
on a =maximizing= model whose marginals came from another GAMS solver (correct
sign) the reconstructed constraint working set is inverted.

* Verdict
SOLVER_BUG — equation marginals are sign-inverted for =maximizing= models in
both GAMS links.  Both links negate POUNCE's \(\lambda\) unconditionally to form
GAMS's \(\pi\), which is correct only for =minimizing= models; for
=maximizing= models the =obj_sign= flip that the same code applies to the
objective and to the variable marginals is missing on the constraint duals.
Confirmed live against GAMS 53.2.0 with an independent solver as oracle, and
reproduced offline with a fake =GmoView=.  Minimizing models — the common case,
and the only case the shipped tests cover — are unaffected; primal solutions,
objective values, reduced costs and status mapping are correct in both senses.
The one-line fix in each link is to scale the negation by =obj_sign=
(equivalently, skip the negation when maximizing).
