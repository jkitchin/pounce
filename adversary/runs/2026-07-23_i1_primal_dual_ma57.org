* Minor observation (NOT a finding)

solver and returns =info["mult_g"] = None=, whereas =solver_selection="nlp"=
returns the correct -0.7071, =solve_socp= exposes the conic dual =z=, and the
CLI/.sol conic path writes the correct -0.7071. So the auto/conic route of the
=minimize= facade drops the recomposed per-constraint dual. This is a
Python-facade parity gap (a missing number, never a wrong one), the same class
as the previously-noted =rc=-suffix gap -- reported as an observation, not a
correctness finding.
