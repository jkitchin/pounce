* Cross-check / Verification
The x-vs-known error (6.95e-6) is entirely IPM boundary-approach slack at
active bounds (items 4, 5 land at e.g. 2.99998 instead of exactly 3.0) — an
expected interior-point property, not a discrepancy; the objective error is
1.5e-11. Crucially, =solve_qp_multi_rhs= agrees with 6 independent
=solve_qp= calls to 0 (exact bitwise/tolerance match), confirming the
shared-factorization multi-RHS code path produces identical results to the
single-solve path it is meant to accelerate.

* Verdict
PASS — =solve_qp_multi_rhs= correctly solves a fixed box-QP structure
against 6 different linear-cost vectors, matching both the closed-form

looped single-solve baseline. This is a fresh probe of a batch API surface
(shared geometry, varying objective) distinct from the previously-logged
=solve_qp_batch= tests (heterogeneous per-item P/A/G).
