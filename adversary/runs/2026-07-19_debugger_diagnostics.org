* FINDING — silent acceptance: find_stalls min_window <= 1

=find_stalls(min_window=0)= and =(min_window=1)= are silently accepted and
return 20 "stall windows" on a solve that converged monotonically with
*zero* stalls (default min_window=5 correctly returns []).

18 of the 20 windows are degenerate: =start_iter == end_iter= with
=delta_log10 = 0.0=. A single iterate cannot stall — a stall is defined
over consecutive iterations, so the minimum meaningful window is 2.

min_window=0 and min_window=1 return *identical* output, so 0 is being
silently coerced to 1 rather than rejected.

Impact: an agent that passes min_window=0/1 gets a plausible-looking,
well-formed answer declaring every iteration of a healthy solve a stall.
Same defect class as issue #213 (silent acceptance of an invalid option).

Suggested fix: reject min_window < 2 with a clear error, as the
neighbouring tools already do for their bad arguments.
