Chosen to be DIFFERENT from the prior qp-active-set runs (avoided: box-bounds QP,
equality+inequality QP, the generic Nocedal--Wright 16.4 CLI run). Here a single
GENERAL linear inequality binds while every nonnegativity bound stays strictly
interior, so the optimal active set is nontrivial for an active-set solver.

* Formulation
#+begin_example
  min  f(x) = 9 - 8 x1 - 6 x2 - 4 x3
              + 2 x1^2 + 2 x2^2 + x3^2 + 2 x1 x2 + 2 x1 x3
  s.t. x1 + x2 + 2 x3 <= 3
       x1, x2, x3 >= 0
#+end_example
Standard QP form min 1/2 x'P x + c'x + r with
  P = [[4,2,2],[2,4,0],[2,0,2]] (SPD),  c = (-8,-6,-4),  r = 9.

Published optimum (Hock--Schittkowski P35): x* = (4/3, 7/9, 4/9), f* = 1/9.
At x*: x1 + x2 + 2 x3 = 4/3 + 7/9 + 8/9 = 3 -> the general inequality is ACTIVE;
x* > 0 componentwise -> all three bounds inactive. Active set = { the inequality }.

* How the active-set path was invoked (and CONFIRMED exercised)
CLI only, identical mechanism to the proven prior runs. QP emitted as a pyomo
=.nl= and run:
#+begin_example
  pounce model.nl out.sol solver_selection=qp-active-set --json-output out.json
#+end_example
=dispatch.rs= maps ="qp-active-set"= -> =SolverChoice::QpActiveSet=; =main.rs=
realizes it via the active-set SQP engine (=algorithm=active-set-sqp= ->
=optimize_sqp_tnlp=, step QPs solved in =pounce-qp=).

The JSON solve-report carries no explicit "algorithm" string, so the path was
confirmed by EXECUTION SIGNATURE instead: the same =.nl= forced through each
selection reports
| selection             | iteration_count |
|-----------------------+-----------------|
| qp-active-set (SUT)   |               1 |
| qp-ipm                |               9 |
| (default, no flag)    |               9 |
The single-iteration count is the active-set engine identifying the binding set
and solving the equality-constrained KKT system directly; it differs from the
9-iteration interior-point count, so qp-active-set did NOT silently fall through
to the IPM. Confirmation flag in the script: as_path_confirmed = True.

IPM cross-check (internal oracle): =pounce.solve_qp= (pounce-convex IPM), with
G x <= h, G = [1,1,2], h = 3, lb = 0. External oracle: cvxpy / CLARABEL.
