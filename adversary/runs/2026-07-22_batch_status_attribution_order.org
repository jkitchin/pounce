#+TITLE: Adversary Run: Batch status ATTRIBUTION under adversarial ordering
#+DATE: <2026-07-22>

* Problem
:PROPERTIES:
:FAMILY: batch
:CLASS: infeasibility / unboundedness / status-reporting correctness
:SOURCE: internal-consistency contract (batch[i] == isolated solve_qp(items[i])) + closed-form KKT per item + cvxpy/CLARABEL per item
:KNOWN_OPTIMAL: analytic per item (see below)
:N_VARIABLES: 3 per item; batches of size 0, 1, 5, 8, 10, 13
:N_CONSTRAINTS: per item: box, 1 equality, or 2 contradictory inequalities
:END:

The 2026-07-19 run ("Mixed-status batch") fixed one infeasible + one unbounded
item at fixed positions. Here the *order* is the attack surface: if
=solve_qp_batch= ever attributed a status or a solution to the wrong index, or
short-circuited on the first failure, permuting the same multiset would expose
it.

Item kinds, each with a closed-form minimiser chosen to be *unique* so that a
misassigned solution is detectable by nearest-neighbour matching:

- =feas_unc(k)=: \(\min \tfrac12 (k{+}1)\|x\|^2 - (k{+}1) t_k^\top x\), box
  \([-50,50]^3\) strictly inactive \(\Rightarrow x^\* = t_k\),
  \(t_k = (1{+}\tfrac k2,\, -\tfrac12-\tfrac k4,\, \tfrac{3k}{10}-1)\).
- =feas_box(k)=: diagonal \(P\), unconstrained minimiser pushed outside
  \([-1,2]^3\) \(\Rightarrow x^\* = \mathrm{clip}(u_k,\,\mathrm{lb},\,\mathrm{ub})\)
  (active-set item).
- =feas_eq(k)=: \(\min \tfrac12\|x\|^2 - t_k^\top x\) s.t. \(\mathbf 1^\top x = k{+}1\)
  \(\Rightarrow x^\* = t_k + (b - \mathbf 1^\top t_k)/n\).
- =infeas(k)=: \(x_0 \le -(1{+}k)\) and \(-x_0 \le -(1{+}k)\) — empty primal.
- =unbd(k)=: \(P=\mathrm{diag}(1,1,0)\), \(c=(0,0,-(1{+}k))\) — unbounded along
  the null direction of \(P\).

Experiments:
(a) all \(5! = 120\) orderings of \(\{F,F,F,\mathrm{INFEAS},\mathrm{UNBD}\}\),
    including infeasible first / middle / last;
(b) a batch in which *all 8* items fail (4 infeasible + 4 unbounded);
(c) exactly one infeasible among 12 feasible, at each of the 13 positions, and
    the mirror image (one feasible among 12 infeasible), plus one unbounded
    among 12 feasible;
(d) batch of size 1 (each kind) and size 0;
(e) neighbour purity: 10 rotations of a 10-item mixed batch, every feasible
    item compared bit-for-bit against an isolated single =solve_qp=.

Findings:

- *(a) Order-independence.* All 120 permutations produced exactly 20 distinct
  status vectors — precisely \(5!/3! = 20\), i.e. the status vector is a pure
  function of the *multiset positions of the two failing items* and nothing
  else. In every permutation the set of non-optimal indices equalled the set of
  positions actually holding a failing item. Infeasible-first, -middle, and
  -last all behaved identically; no evidence of a first-failure short circuit
  (items after the failure are still solved, and correctly).
- *(b) All-fail batch.* 8/8 items returned their own correct failure status —
  4 =primal_infeasible=, 4 =dual_infeasible=, correctly distinguished; nothing
  reported =optimal=, and no exception escaped.
- *(c) Singleton sweeps.* One infeasible among 12 feasible: for each of the 13
  insertion positions the non-optimal index set was exactly ~[pos]~. Mirror
  case (one feasible among 12 infeasible): the optimal index set was exactly
  ~[pos]~ for all 13 positions — a single survivor is not swallowed by a batch
  of failures. Same for one unbounded item at positions 0, 6, 12.
- *(d) Edge sizes.* Size-1 batches reproduce the isolated solve for all three
  kinds (=optimal=, =primal_infeasible=, =dual_infeasible=). Size-0 returns
  ~[]~ cleanly, no error.
- *(e) Neighbour purity.* Across 10 rotations of a 10-item mixed batch, every
  feasible item's =x= was *bit-identical* (max abs diff exactly ~0.0~, not
  merely within tolerance) to both (i) its answer at every other position and
  (ii) the isolated single =solve_qp=. Objective matched the analytic optimum
  to <1e-8 relative. No feasible item's solution ever best-matched another
  item's true minimiser (minimisers separated by >= 0.5 in the inf-norm, so
  such a swap would have been unmissable).

* Cross-check / Verification
Three independent oracles per feasible item: (1) isolated single =solve_qp=,
(2) cvxpy/CLARABEL on the same data (=psd_wrap= used because =feas_box= /
=unbd= carry a diagonal/singular \(P\)), (3) closed-form KKT. All three agree
to <=1.4e-8. For the failing items cvxpy independently reports =infeasible= /
=unbounded= matching pounce's =primal_infeasible= / =dual_infeasible=, so the
status labels are not merely self-consistent.

One false positive was found and fixed *in the script*, not in pounce: the
first =feas_unc= construction let \(t_k\) run past the box bound for
\(k \ge 9\), so the "analytic" minimiser was wrong (the true answer was
clamped) and two items collapsed onto the same clamped point. Widening the box
to \([-50,50]\) and rescaling \(t_k\) removed all 112 apparent failures — the
pounce answers had been correct throughout (they matched the isolated solve
bit-for-bit even while disagreeing with my bad analytic value). This is the
usual FORMULATION_ERROR trap; recorded here so the near-miss is on the record.

* Verdict
PASS — =solve_qp_batch= attributes statuses and solutions to the ITEM, never to
the position. 5107 assertions over 120 permutations, an all-failing batch, 39
singleton-position sweeps, size-0/1 edge cases and 10 rotations produced zero
divergences, with feasible neighbours bit-identical to isolated single solves.
No early failure short-circuits later items, and =primal_infeasible= vs
=dual_infeasible= is correctly distinguished per item and confirmed by cvxpy.
Total runtime 0.57 s, well inside budget.
