* Problem

** Surfaces tested (all PYTHON API -- no =.sol= file involved)
| entry point         | duals inspected                                 |

This is deliberately *not* the =.sol= surface, so the known dual-sign finding
on the =.sol= writer cannot contaminate the (d)/(e) dual-scaling results.

** Dual sign conventions (re-derived in-script, not assumed)
Every instance's baseline solve is checked against an independently coded KKT
stationarity residual before any transformation is applied. Both surfaces use
the *Ipopt convention*:

\[
\text{solve\_qp:}\quad Px + c + A^\top y + G^\top z - z_{lb} + z_{ub} = 0,\qquad z, z_{lb}, z_{ub}\ge 0
\]
\[
\text{minimize:}\quad \nabla f + J^\top \lambda_g - \lambda_{x_L} + \lambda_{x_U} = 0
\]

Baseline stationarity residuals: =solve_qp= max 1.7e-11, =minimize= max 6.4e-11.
The conventions are therefore confirmed, and the dual invariants below are
meaningful.

** Transformations applied
Each is a provable identity of the mathematical program; for scalings only
positive factors are used (alpha in {0.1, 0.2, 3, 5, 2.5}, beta in {0.25, 3, 4, 6}).

- *(a)* permute variable order (P, c, A, G, lb, ub all permuted correspondingly)
- *(b)* permute constraint rows / cone blocks
- *(c)* f -> f + K (K = 17.25); =minimize= only -- the QP/SOCP standard form
  carries no constant term
- *(d)* f -> alpha*f, alpha>0: same argmin, obj*alpha, *all duals*alpha*
- *(e)* scale one constraint row by beta>0: same primal, *that dual * 1/beta*
- *(f)* x -> x + s with all data adjusted (c -> c - Ps, b -> b + As, h -> h + Gs,
  bounds shifted); note the reported objective *drops* the constant
  (0.5 s'Ps - c's), which the script accounts for
- *(g)* split an equality a'x=b into a'x<=b and -a'x<=-b, also checking the dual
  recovery y_0 = z_+ - z_-
- *(h)* add a redundant row implied by existing ones (a convex combination of
  two active rows; a positively scaled duplicate for =minimize=)
- *(i)* append a variable appearing in no constraint (separable 0.5 w^2 term so
  the problem stays bounded, w* = 0, objective unchanged)

183 invariance checks total.

** Narrative
The dual-scaling invariants are the headline result, and they hold cleanly:

- *(d)* every multiplier family scales *linearly with alpha*. =solve_qp= =y=,
  =z=, =z_lb=, =z_ub= agree with alpha*dual to <=1.0e-9 at default tolerance
  (<=2.4e-11 at tol=1e-10); =minimize= =mult_g= agrees to <=2.6e-10 over
  alpha in {0.2, 5}. There is no sign flip and no missing scaling anywhere.
- *(e)* scaling a single constraint row by beta divides *exactly that row's*
  dual by beta and leaves every other dual and the whole primal untouched --
  verified separately for =solve_qp= inequality rows (dev 2.8e-10), equality
  rows (1.2e-12), whole SOC blocks (6.2e-08 -> 8.3e-09 tightened), and
  =minimize= nonlinear rows (1.7e-09). The active row with the largest dual was
  deliberately chosen as the scaling target, so the check is not vacuous.
- *(c)* is exactly neutral for the multipliers: =mult_g= is *bit-identical*
  (deviation 0.0) after f -> f + 17.25, and the objective shifts by exactly K
  (1.6e-15).
- *(b)* constraint permutation is essentially *bit-exact* on both =solve_qp=
  (4e-16) and =minimize= (0.0 on =nlp_sphere_eq=), with duals permuted
  correspondingly -- pounce's ordering handling is deterministic and
  permutation-equivariant, including =z_lb= / =z_ub= under (a).
- *(g)* the split-equality dual recovery holds: y_0 = z_+ - z_- to 7.5e-12
  (=solve_qp=), and mult_k = m_+ - m_- to 9.8e-09 (=minimize=).
- *(i)* adding a variable that appears in no constraint leaves the other
  variables and all multipliers untouched (0.0 in several cases).

* Cross-check / Verification
No external solver is required -- the invariant *is* the oracle. Three
independent guards were nonetheless applied so that a scripting mistake could
not masquerade as a pass or a failure:

1. *KKT stationarity re-derivation.* Each baseline solve is fed to a
   hand-coded stationarity residual using only the raw problem data and the
   returned duals. All baselines are <=1.7e-11, which pins the sign convention
   and proves the dual arrays are being read correctly.
2. *A genuine formulation error was found and fixed by this guard.* The first
   run flagged (f) variable-shift objective violations of order 1.0 on
   *every* instance while =x - shift= was correct to 1e-11. That was the
   script's sign, not pounce's: =solve_qp= / =solve_socp= report
   0.5 w'Pw + c_new'w, which omits the shift constant, so the identity is
   obj_new + const = obj_old, not obj_new - const = obj_old. Corrected, the
   deviation drops to 1.3e-08. Recorded here because it is exactly the class of
   error the skill warns is likelier than a solver bug.
3. *Independent high-precision reduction for the one residual deviation.*
   =socp_qobj_eq= reduces (via x2 = 0.5 - x1 and t = ||(x1+0.3, x2-0.2)||) to
   the 1-D problem min x1^2 + x2^2 + t - x1 + 0.5 x2. =scipy.optimize.minimize_scalar=
   (Brent, xtol=1e-14) gives x1* = 0.35496809002638086, F* = 0.5218551015125126.
   Sweeping alpha at tol=1e-10:

   | alpha | pounce x1        | x1 err   | obj/alpha err | kkt_error | iters |
   |-------+------------------+----------+---------------+-----------+-------|
   |   0.1 | 0.354968087574   | -2.4e-09 |       2.2e-16 |   1.4e-17 |    46 |
   |   1.0 | 0.354968077190   | -1.3e-08 |      -1.3e-15 |   1.4e-15 |    31 |
   |   2.5 | 0.354967107604   | -9.8e-07 |      -3.4e-13 |   2.4e-11 |    38 |
   |  10.0 | 0.354968090909   |  8.8e-10 |       2.2e-16 |   1.8e-15 |    42 |

   pounce's objective is invariant to *1e-13 or better at every alpha*, and the
   reported KKT residual is at machine precision. The argmin moves by up to
   1e-6 purely because the objective is locally quadratic with curvature ~4:
   obj_err ~ 4 * x_err^2 = 4 * (1e-6)^2 ~ 4e-12, which is precisely what the
   table shows. This is the textbook sqrt(tolerance) resolution of an argmin in
   a flat direction, and it is why the skill instructs grading degenerate/flat
   cases on objective + feasibility. On that basis the instance passes: the
   objective invariant holds at 3.4e-13 and primal feasibility at 4.3e-15.

* Verdict
*PASS* (with a =TOLERANCE=-class note). All 183 metamorphic checks across
=minimize=, =solve_qp= and =solve_socp= satisfy their exact mathematical
invariant. The dual-scaling laws that were the focus of this run -- objective
scaling multiplying every multiplier by alpha, and constraint-row scaling
dividing exactly that row's multiplier by beta -- hold to 1e-9..1e-12 on the
Python API on every surface, including =z_lb= / =z_ub= and =minimize='s
=mult_g=. Permutation equivariance is essentially bit-exact. The only
deviations above 1e-6 are argmin coordinates on =socp_qobj_eq=, an instance
with a flat direction, where the objective and feasibility invariants hold at
1e-13 and every deviation shrinks by 3-4 orders of magnitude with =tol=1e-10=;
that is ordinary interior-point termination behaviour, not a defect. No
SOLVER_BUG. The one genuinely wrong result seen during the run was a sign error
in this adversary script's variable-shift constant, which the KKT guard caught.
